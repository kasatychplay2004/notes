# Проект: сегментация корпоративной сети

Проектирование адресного плана и правил межсегментной фильтрации
для сети из диапазона `10.50.0.0/16`.

## Задача

Спроектировать изолированные сегменты для отделов с разными
требованиями к доверию и объёму, минимизировать возможность
бокового перемещения при компрометации одного из сегментов.

## Требования по количеству устройств

| Сегмент | Устройств | Уровень доверия |
|---|---|---|
| Рабочие станции | 200 | средний |
| Серверы | 20 | высокий |
| Бухгалтерия | 10 | высокий, критичные данные |
| Гостевой Wi-Fi | 100 | **нулевой** |
| Камеры / IoT | 50 | **низкий** |

## Адресный план

| Сегмент | Подсеть | Маска | Ёмкость | Запас |
|---|---|---|---|---|
| Рабочие станции | 10.50.10.0 | /24 | 254 | 54 |
| Серверы | 10.50.20.0 | /27 | 30 | 10 |
| Бухгалтерия | 10.50.30.0 | /28 | 14 | 4 |
| Гостевой Wi-Fi | 10.50.40.0 | /25 | 126 | 26 |
| Камеры | 10.50.50.0 | /26 | 62 | 12 |

**Обоснование выбора масок:** для каждого сегмента взята минимальная
маска, вмещающая требуемое количество устройств с разумным запасом.
Избыточно крупные сегменты нежелательны — чем больше машин в одном
широковещательном домене, тем шире обзор атакующего при компрометации
любой из них.

**Обоснование нумерации:** третий октет выделен с шагом 10, чтобы
оставить пространство для новых сегментов без переработки схемы.

## Правила межсегментной фильтрации

### Гостевой Wi-Fi — полная изоляция
ЗАПРЕТИТЬ 10.50.40.0/25 → 10.50.0.0/16
РАЗРЕШИТЬ 10.50.40.0/25 → интернет
Гостевые устройства не контролируются организацией и потенциально
скомпрометированы. Единственная законная задача сегмента — выход
в интернет. Это наиболее вероятная точка входа при атаке.

### Камеры — только видеосервер
РАЗРЕШИТЬ 10.50.50.0/26 → 10.50.20.5:554
ЗАПРЕТИТЬ 10.50.50.0/26 → ЛЮБОЙ
IoT-устройства редко обновляются и содержат известные уязвимости.
Камера не имеет причин инициировать соединения куда-либо, кроме
своего видеосервера. Любая другая активность из этого сегмента —
признак компрометации.

Порядок правил важен: конкретное разрешение выше общего запрета,
так как правила обрабатываются сверху вниз до первого совпадения.

### Бухгалтерия — доступ только исходящий
ЗАПРЕТИТЬ 10.50.10.0/24 → 10.50.30.0/28
РАЗРЕШИТЬ 10.50.30.0/28 → 10.50.20.0/27
Сегмент содержит финансовые данные. Обычные рабочие станции не имеют
причин обращаться к машинам бухгалтерии напрямую. Обмен данными
организуется через серверный сегмент, где логирование и контроль.

### Рабочие станции — принцип наименьших привилегий
РАЗРЕШИТЬ 10.50.10.0/24 → 10.50.20.0/27:443
ЗАПРЕТИТЬ 10.50.10.0/24 → 10.50.20.0/27
Доступ к серверам открыт только к необходимым службам, а не
к сегменту целиком. Это ограничивает возможности разведки
и эксплуатации при заражении рабочей станции.

### Anti-spoofing на границе
ЗАПРЕТИТЬ источник 10.0.0.0/8 из интернета
ЗАПРЕТИТЬ источник 172.16.0.0/12 из интернета
ЗАПРЕТИТЬ источник 192.168.0.0/16 из интернета
Частные адреса не маршрутизируются в интернете. Пакет с таким
источником, пришедший снаружи, заведомо подделан — попытка обойти
правила, доверяющие внутренним адресам.

## Достигнутый результат

- Компрометация гостевого сегмента не даёт доступа к внутренней сети
- Компрометация камеры не позволяет перемещаться к другим устройствам
- Заражение рабочей станции не открывает прямой путь к финансовым данным
- Подделка внутренних адресов извне блокируется на периметре

## Ограничения решения

Схема покрывает сетевую сегментацию, но не является полной моделью
защиты. За рамками остались:

- Контроль трафика **внутри** сегмента (устройства одного сегмента
  видят друг друга напрямую)
- Аутентификация устройств при подключении к сети (802.1X)
- Микросегментация серверного сегмента
- Мониторинг и логирование межсегментных отказов

В продуктивной среде сетевую сегментацию следует дополнять
контролем на уровне хостов и централизованным сбором событий.
