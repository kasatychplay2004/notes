# IP-адресация и подсети

**Модуль 1, сессия 3**

## Зачем это нужно

1. **Сегментация сети** — базовая мера защиты, делается через подсети
2. **Правила файрвола** пишутся в терминах подсетей — ошибка в маске
   означает открытый доступ не тем, кому предполагалось
3. **Расследование инцидентов** — постоянный вопрос «свой или чужой»,
   из какого сегмента, должен ли он туда ходить

---

## Структура IP-адреса

IPv4 = **32 бита**, записывается как четыре октета по 8 бит:
192.168.1.72
11000000 . 10101000 . 00000001 . 01001000
Всего адресов: 2³² ≈ 4,3 млрд. Мало для планеты → отсюда NAT и IPv6.

Адрес состоит из **двух частей**: номер сети + номер хоста в ней.
192.168.1.72

└──┬───┘ └┬┘
сеть хост
**Зачем деление:** не для увеличения количества адресов, а для
**иерархии и агрегации маршрутов**. Роутер хранит одну запись
«сеть 192.168.1.0/24 → туда» вместо 254 отдельных. Без этого
таблицы маршрутизации в интернете были бы неподъёмными.

---

## Маска подсети

Задаёт границу между частью сети и частью хоста.
IP: 192.168.1.72 11000000.10101000.00000001.01001000
Маска: 255.255.255.0 11111111.11111111.11111111.00000000

└────── сеть ──────────┘ └─ хост ─┘
**Правило:** в маске сначала только единицы, потом только нули.
Чередования не бывает. Поэтому маску записывают одним числом —
сколько единиц: `/24`, `/26`. Это **CIDR-нотация**.

| CIDR | Маска | Хостов |
|---|---|---|
| /24 | 255.255.255.0 | 254 |
| /25 | 255.255.255.128 | 126 |
| /26 | 255.255.255.192 | 62 |
| /27 | 255.255.255.224 | 30 |
| /28 | 255.255.255.240 | 14 |
| /29 | 255.255.255.248 | 6 |
| /30 | 255.255.255.252 | 2 |

Значения последнего октета (128, 192, 224, 240...) — суммы старших битов:
`128`, `128+64=192`, `128+64+32=224` и т.д.

## Три особых адреса в подсети

| Адрес | Что это |
|---|---|
| **Первый** (биты хоста = 0) | адрес сети, не назначается устройствам |
| **Последний** (биты хоста = 1) | broadcast, получают все в подсети |
| Всё между | адреса хостов |
Хостов = 2^(битов хоста) − 2
Минус два — как раз адрес сети и broadcast.

---

## Метод расчёта подсети

**Задача:** `192.168.1.72/26`

**Шаг 1.** Битов хоста: `32 − 26 = 6`

**Шаг 2.** Размер блока: `2⁶ = 64`

Быстрый способ: **`256 − последний октет маски`**
Для /26 маска 255.255.255.192 → `256 − 192 = 64` ✓

**Шаг 3.** Границы идут по кратным 64:
0–63 | 64–127 | 128–191 | 192–255

**Шаг 4.** `.72` попадает в блок 64–127:
Адрес сети: 192.168.1.64
Broadcast: 192.168.1.127
Хосты: 192.168.1.65 – 192.168.1.126 (62 шт)
### Разбиение на N подсетей

Каждый дополнительный бит удваивает количество:
+1 бит → 2 подсети
+2 бита → 4 подсети
+3 бита → 8 подсетей
Пример: `/24` разбить на 4 → занять 2 бита → `/26`, размер блока 64.

## Частные и публичные адреса

**Частные диапазоны** (RFC 1918) не маршрутизируются в интернете:

| Диапазон | CIDR | Где встречается |
|---|---|---|
| 10.0.0.0 – 10.255.255.255 | 10.0.0.0/8 | крупные корпоративные сети |
| 172.16.0.0 – 172.31.255.255 | 172.16.0.0/12 | средние сети, Docker |
| 192.168.0.0 – 192.168.255.255 | 192.168.0.0/16 | дом, малый офис |

Выход в интернет через них работает благодаря **NAT**.

### Особые адреса

| Адрес | Значение |
|---|---|
| 127.0.0.0/8 | loopback, «сам себе» |
| **169.254.0.0/16** | **APIPA — DHCP не ответил** |
| 0.0.0.0 | «любой» или «не назначен» |
| 255.255.255.255 | широковещание в сегменте |

⚠️ **Адрес 169.254.x.x** = машина не получила настройки от DHCP
и назначила адрес сама. Интернета не будет. Искать: сервер DHCP лёг,
кабель не в той сети, порт коммутатора в неправильном VLAN.
Одна из самых частых проблем в helpdesk.

## 🔴 Security-применение

### Анализ направления трафика

| Направление | Что означает |
|---|---|
| внутренний → внутренний | обычный трафик внутри сети |
| внутренний → внешний | исходящее (проверить куда и зачем) |
| внешний → внутренний | входящее (должно ли проходить?) |
| **внутренний адрес пришёл снаружи** | ❗ **подделка (spoofing)** |

Пакет с адресом `192.168.1.50`, пришедший из интернета, физически
не может быть легитимным — такие адреса провайдеры отбрасывают.
Значит источник подделан, чтобы обойти правила «внутренним разрешено».

Правило, блокирующее такое, — **anti-spoofing**, обязательно
на любой границе сети.

### Сегментация

Плоская сеть = подарок атакующему: взломав одну машину, он видит все.

Сегментация разрезает сеть на изолированные части. Трафик между ними
идёт только через маршрутизатор → его можно фильтровать.

**Эффект:** взлом гостевого Wi-Fi или камеры не даёт доступа
к бухгалтерии. Атака остаётся запертой в своём сегменте — это
**ограничение бокового перемещения (lateral movement)**.

**Принцип выбора размера:** сегмент должен быть настолько мал,
насколько это практично. Чем больше сегмент, тем больше машин
увидят друг друга при взломе одной.

## Что запомнить

1. Размер блока = `256 − последний октет маски`
2. Хостов = размер блока − 2
3. `169.254.x.x` → DHCP не ответил
4. Частный адрес из интернета → спуфинг
5. Деление на подсети нужно для агрегации маршрутов, а не для
   увеличения количества адресов
