# Модель OSI, инкапсуляция, MTU

**Модуль 1, сессия 1**

## Зачем это нужно

**Диагностика.** Вопрос «на каком уровне проблема?» сокращает область поиска
в разы. Пинг идёт, сайт не открывается → L1-L3 в порядке, копай выше.
Пинга нет вообще → L3 или ниже.

**Безопасность.** У каждого уровня свои атаки и свои средства защиты.
Атакующий выбирает уровень: перехват в локальной сети → L2 (ARP),
обход файрвола → прячем данные в разрешённый L7-протокол (DNS-туннель).

## Семь уровней OSI

### L1 — Физический
Передача **битов** по среде. Никакой логики, никаких адресов — только сигналы.

- Кабели, радио, разъёмы, напряжения, кодирование сигнала
- Устройства: концентратор, повторитель, медиаконвертер
- 🔴 Физический доступ = полный проигрыш. Врезка в кабель, свободный порт,
  прослушка оптики. Отсюда контроль доступа в серверные и отключение
  неиспользуемых портов коммутатора.

### L2 — Канальный
Передача **кадров** между узлами **в пределах одного сегмента**. Адресация по MAC.

- Ethernet, Wi-Fi, VLAN, ARP, контрольная сумма FCS
- Устройства: **коммутатор**, точка доступа, сетевая карта
- MAC — 48 бит, в hex: `00:1A:2B:3C:4D:5E`
- Подуровни: LLC (интерфейс к L3) и MAC (доступ к среде)
- 🔴 Проектировался для доверенной среды, встроенной защиты почти нет.
  ARP spoofing, MAC flooding, VLAN hopping.

### L3 — Сетевой
Доставка **пакетов** между **разными сетями**. Адресация по IP, маршрутизация.

- IP (v4/v6), ICMP, фрагментация
- Устройства: **маршрутизатор**, L3-коммутатор
- 🔴 IP источника легко подделать → атаки с усилением. Здесь работают ACL.

### L4 — Транспортный
Доставка **до конкретного приложения**. Адресация — порты (16 бит, 0–65535).

- TCP, UDP, контроль потока
- Единица: сегмент (TCP) / датаграмма (UDP)
- **IP + порт = сокет**
- 🔴 Здесь работает stateful-файрвол. Сканирование портов — тоже L4.

### L5 — Сеансовый
Установление и поддержание сессий. На практике в TCP/IP почти растворён
в приложениях. Формально: NetBIOS, RPC, управление сессиями SMB.

### L6 — Представления
Преобразование формата: кодировки, сжатие, шифрование.
ASCII/UTF-8, Base64, JPEG, TLS.

### L7 — Прикладной
HTTP(S), DNS, SMTP, SSH, FTP, SMB, RDP, LDAP.

🔴 Большинство современных атак — здесь: фишинг, SQLi, XSS, вложения.
Отсюда WAF, почтовые шлюзы, прокси с инспекцией.

## Модель TCP/IP

OSI — теоретическая модель. Интернет построен по TCP/IP, который появился
раньше и победил на практике.

| OSI | TCP/IP |
|---|---|
| L7 / L6 / L5 | **Application** |
| L4 | **Transport** |
| L3 | **Internet** |
| L2 / L1 | **Network Access** |

> **Думай по TCP/IP, говори по OSI.** В индустрии прижился жаргон
> «проблема на втором уровне», «L7-файрвол» — это номера OSI.

Реальность грязнее любой модели: TLS не ложится ровно ни в один уровень,
ARP — между L2 и L3, MPLS называют «L2.5». Модель — карта, а не территория.

## Инкапсуляция

Каждый уровень добавляет свой заголовок — как вкладывание письма в конверты.
L7 [ HTTP-данные ]

L4 [TCP hdr][ HTTP-данные ] = СЕГМЕНТ
порты, seq/ack

L3 [IP hdr][TCP hdr][ HTTP-данные ] = ПАКЕТ
src/dst IP, TTL

L2 [MAC hdr][IP hdr][TCP hdr][ данные ][FCS] = КАДР
src/dst MAC ↑
единственный уровень с трейлером

L1 → биты в кабель
На приёме — **декапсуляция**: каждый уровень снимает свой заголовок
и передаёт содержимое выше.

### ⚠️ Главное правило адресации

> **MAC меняется на каждом переходе между сегментами.
> IP остаётся неизменным от источника до получателя.**
Участок 1: ПК → Роутер1
IP: 192.168.1.10 → 203.0.113.50
MAC: MAC(ПК) → MAC(Роутер1)

Участок 2: Роутер1 → Роутер2
IP: 192.168.1.10 → 203.0.113.50 ← без изменений
MAC: MAC(Роутер1) → MAC(Роутер2) ← новые

Участок 3: Роутер2 → Сервер
IP: 192.168.1.10 → 203.0.113.50 ← без изменений
MAC: MAC(Роутер2) → MAC(Сервера) ← новые

**Почему:** MAC работает только внутри сегмента — как номер квартиры,
осмысленный лишь внутри дома. IP — полный почтовый адрес, работает откуда угодно.

Роутер на каждом шаге разбирает кадр до L3, смотрит IP назначения,
решает куда дальше и **упаковывает пакет в новый кадр**.

**Следствия:**
- Коммутатор работает на L2 — про IP не знает вообще
- Роутер работает на L3 — разворачивает, решает, переупаковывает
- MAC удалённого атакующего до тебя не доходит — виден только MAC
  последнего роутера. Зато внутри своей сети MAC → привязка
  к конкретному физическому устройству (инструмент расследования)

## MTU и фрагментация

**MTU** — максимальный размер полезной нагрузки кадра. Ethernet — **1500 байт**.

MSS (TCP) = MTU − 20 (IP) − 20 (TCP) → 1460 при MTU 1500
Данные (UDP/ICMP) = MTU − 20 (IP) − 8 → 1472 при MTU 1500

**MSS** — максимум данных в одном TCP-сегменте, согласуется при рукопожатии.
Берётся минимальное из предложенных обеими сторонами.

### Если пакет больше MTU

**1. Фрагментация.** Роутер режет пакет на части, получатель собирает.
Работает, но плохо: потеря одного фрагмента → переотправка всего;
сборка нагружает получателя; фрагменты используют для обхода IDS.

**2. Флаг DF (Don't Fragment).** Роутер отбрасывает пакет и шлёт обратно
ICMP «Fragmentation Needed» с указанием своего MTU. Отправитель уменьшает
размер и повторяет. Это **Path MTU Discovery (PMTUD)**.

### 🔴 PMTUD black hole

Администратор «для безопасности» блокирует весь ICMP:

1. Соединение устанавливается — пакеты маленькие ✓
2. Начинается передача данных — пакеты большие, с флагом DF
3. Промежуточный роутер (VPN/PPPoE с MTU < 1500) не может их пропустить
4. Отбрасывает и шлёт ICMP «Fragmentation Needed»
5. **Файрвол блокирует этот ICMP**
6. Отправитель не получил обратной связи → шлёт пакеты того же размера
7. Они молча пропадают

**Симптом:** пинг идёт, соединение устанавливается, лёгкие страницы
открываются — а загрузка файлов и TLS зависают. Без единой ошибки в логах.

**Проверка:**
ping -f -l 1472 8.8.8.8 # Windows
ping -M do -s 1472 8.8.8.8 # Linux

Прошло 1472, не прошло 1473 → MTU пути = 1500.

**Вывод:** блокировать ICMP целиком — вредная практика. ICMP несёт служебную
информацию, нужную для работы сети. Фильтровать избирательно, обязательно
пропуская Fragmentation Needed и Time Exceeded.

## ⚠️ Что запомнить

1. **MTU — это L2, не L4.** Транспортный уровень лишь страдает от последствий
2. **«Соединение есть, данные не идут» → в первую очередь проверяй MTU**
3. **Транспортный уровень — только TCP и UDP.** HTTP, SMTP, DNS, SSH — всё L7
4. MAC меняется на каждом хопе, IP — нет
5. Заголовок L4 в расчётах всегда один: либо TCP (20), либо UDP/ICMP (8)

## Практические выводы

- Шифрование (HTTPS) скрывает содержимое L7, но **не метаданные**:
  кто, с кем, когда, сколько — видно всегда
- Wireshark расшифровывает первые 3 байта MAC (OUI) в имя производителя —
  рабочий приём при инвентаризации сети
- Разные MSS в ответах серверов показывают разные узкие места путей
  (1360, 1412 — типичные значения для туннелей и VPN)
