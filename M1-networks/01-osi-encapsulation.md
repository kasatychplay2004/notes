# Модель OSI, инкапсуляция, MTU

Две причины, по которым модель OSI — не абстракция для экзамена, а рабочий инструмент.

Первая: диагностика. Когда что-то не работает, вопрос «на каком уровне проблема?» сокращает область поиска в разы. Пинг идёт, а сайт не открывается — значит L1-L3 в порядке, копай выше. Пинга нет вообще — L3 или ниже. Это экономит часы.
Вторая — специфически security: у каждого уровня свои атаки и свои средства защиты.

## 1. Семь уровней OSI

**L1 — Физический**

Передача битов по среде. Никакой логики, никаких адресов — только сигналы.

Что здесь: кабели (медь, оптика), радио, разъёмы, напряжения, частоты, кодирование сигнала
Устройства: концентраторы (hub), повторители, медиаконвертеры
Единица данных: бит
Security: физический доступ = полный проигрыш. Врезка в кабель, подключение к свободному порту, прослушка оптики. Отсюда контроль доступа в серверные и отключение неиспользуемых портов коммутатора.

**L2 — Канальный (Data Link)**

Передача кадров между узлами в пределах одного сегмента сети. Адресация по MAC.

Что здесь: Ethernet, Wi-Fi (802.11), VLAN, ARP (формально между L2 и L3), обнаружение ошибок (FCS)
Устройства: коммутатор (switch), точка доступа, сетевая карта
Единица данных: кадр (frame)
Адрес: MAC, 48 бит, записывается в hex — 00:1A:2B:3C:4D:5E

Разделяется на два подуровня: LLC (интерфейс к L3) и MAC (доступ к среде).

Security: L2 проектировался в доверенной среде и почти не имеет встроенной защиты. Отсюда ARP spoofing, MAC flooding, VLAN hopping — целый класс атак, который мы разберём отдельно.

**L3 — Сетевой**

Доставка пакетов между разными сетями. Адресация по IP, выбор пути — маршрутизация.

Что здесь: IP (v4/v6), ICMP, маршрутизация, фрагментация
Устройства: маршрутизатор (router), L3-коммутатор
Единица данных: пакет (packet)
Адрес: IP — глобально осмысленный, в отличие от MAC

Security: IP-адрес источника легко подделать (spoofing) — на этом строятся атаки с усилением. Здесь же работают ACL и базовая фильтрация.

**L4 — Транспортный**

Доставка между конкретными приложениями на хостах. Адресация — порты.

Что здесь: TCP, UDP, порты, надёжность, контроль потока
Единица данных: сегмент (TCP) / датаграмма (UDP)
Адрес: порт, 16 бит (0-65535)

Ключевая идея: L3 доставляет до машины, L4 — до конкретного приложения на ней. Комбинация IP + порт называется сокет.

Security: здесь живёт stateful-файрвол. Сканирование портов — тоже L4.

**L5 — Сеансовый**

Установление, поддержание и завершение сессий между приложениями. Контрольные точки для возобновления.

На практике в TCP/IP-мире почти растворён в приложениях. Формально сюда относят NetBIOS, RPC, частично управление сессиями в SMB.

**L6 — Представления**

Преобразование формата данных: кодировки, сжатие, шифрование.

Здесь ты видишь сегодняшнюю Сессию 0 в действии: ASCII/UTF-8, Base64, JPEG, а также TLS-шифрование (формально его относят к L6, хотя в TCP/IP-модели это спорно).

**L7 — Прикладной**

Интерфейс для приложений пользователя.

Протоколы: HTTP(S), DNS, SMTP, SSH, FTP, SMB, RDP, LDAP
Единица: данные (data)

Security: большинство современных атак — здесь. Фишинг, SQLi, XSS, вредоносные вложения. Отсюда WAF, почтовые шлюзы, прокси с инспекцией.

## 2. Модель TCP/IP — то, как есть на самом деле

**OSI (7 уровней)	TCP/IP (4 уровня)**

L7 Прикладной	Application

L6 Представления	(входит в Application)

L5 Сеансовый	(входит в Application)

L4 Транспортный	Transport

L3 Сетевой	Internet

L2 Канальный	Network Access

L1 Физический	(входит в Network Access)


Что использовать на практике: думай по TCP/IP, говори по OSI. В индустрии прижился жаргон «проблема на втором уровне», «L7-файрвол», «L3-коммутатор» — это номера OSI. Но реальные протоколы устроены по TCP/IP.

## 3. Инкапсуляция — сердце темы

Вот что реально происходит с данными при отправке. Каждый уровень добавляет свой заголовок — как вкладывание письма в конверты.
На приёме — обратный процесс, декапсуляция: каждый уровень снимает свой заголовок и передаёт содержимое выше.


L7  Данные приложения:
   
    ┌─────────────────────────────────────┐
    │ GET /index.html HTTP/1.1 ...        │
    └─────────────────────────────────────┘


L4  + TCP-заголовок (20 байт):
   
    ┌──────────┬──────────────────────────┐
    │ TCP hdr  │ HTTP-данные              │   = СЕГМЕНТ
    │ порты,   │                          │
    │ seq/ack  │                          │
    └──────────┴──────────────────────────┘


L3  + IP-заголовок (20 байт):
   
    ┌─────────┬──────────┬────────────────┐
    │ IP hdr  │ TCP hdr  │ HTTP-данные    │   = ПАКЕТ
    │ src/dst │          │                │
    │ IP, TTL │          │                │
    └─────────┴──────────┴────────────────┘


L2  + MAC-заголовок (14 байт) + FCS (4 байта):
   
    ┌────────┬─────────┬──────────┬───────────┬─────┐
    │ MAC hdr│ IP hdr  │ TCP hdr  │ HTTP-данные│ FCS │  = КАДР
    │src/dst │         │          │            │     │
    │  MAC   │         │          │            │     │
    └────────┴─────────┴──────────┴───────────┴─────┘


L1  → биты в кабель

**ВАЖНО!!!!!!!!**
MAC-адреса меняются на каждом переходе между сегментами. IP-адреса остаются неизменными от источника до получателя.

## 4. MTU и фрагментация

**MTU (Maximum Transmission Unit)** — максимальный размер полезной нагрузки кадра. Для классического Ethernet — 1500 байт.
MTU = 1500 байт
  − 20 байт IP-заголовок
  − 20 байт TCP-заголовок
  ─────────────────────
  = 1460 байт полезных данных  ← это MSS

  UDP = 8

  Что если пакет больше MTU

**Два сценария:**

1. Фрагментация. Роутер режет IP-пакет на части, каждая идёт отдельно, получатель собирает обратно. Работает, но плохо: если потеряется один фрагмент — переотправлять придётся всё; сборка нагружает получателя; фрагменты используют для обхода IDS.

2. Флаг DF (Don't Fragment). Пакет помечен «не фрагментировать». Роутер, не способный его пропустить, отбрасывает пакет и отправляет обратно ICMP-сообщение «Fragmentation Needed» с указанием своего MTU. Отправитель уменьшает размер и повторяет.

Администратор «для безопасности» блокирует весь ICMP на файрволе. Что происходит:

TCP-соединение устанавливается нормально — пакеты маленькие
Начинается передача данных — пакеты большие, с флагом DF
Промежуточный роутер (например, с VPN или PPPoE, где MTU меньше 1500) не может их пропустить
Он отбрасывает пакет и шлёт ICMP «Fragmentation Needed»
Файрвол блокирует этот ICMP
Отправитель не получает обратной связи, продолжает слать пакеты того же размера
Они молча пропадают


**ВАЖНО!!!!!**
Проблема MTU - иди на канальный уровень
